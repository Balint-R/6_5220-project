\begin{abstract}
We examine existing algorithms for the text-to-pattern Hamming distance problem, focusing on an approximate $O(\eps^{-1} n \log n \log m)$ time FFT-based sampling algorithm and an $O(n \sqrt{m \log m})$ time exact one.
We first describe and motivate these algorithms.
Next, we suggest some optimization techniques and heuristics that benefit actual implementations of these algorithms.
Finally, we implement the algorithms and examine their performance on different types of inputs.
\end{abstract}

\section{Preliminaries}
\subsection{Problem Description}

For two strings $S, T$ of the same length, let $\op{HAM}(S, T)$ denote the regular Hamming distance between $S$ and $T$.
i.e. the number of indices $i$ such that the $i$-th character of $S$ is different from the $i$-th character of $T$.
We study algorithms that compute or approximate the Hamming distance between a pattern string and every offset of a text string.

\begin{definition}[Text-to-pattern Hamming distance] \label{def:ham_exact}
    Let $T = t_1 t_2 \ldots t_n$ be a string of length $n$ and $P = p_1 p_2 \ldots p_m$ be a string of length $m$ with $m \leq n$.
    For each $m$ character substring $T_i$ of $T$, let $d_i = \op{HAM}(T_i, P)$.
    The exact version of the problem requires the algorithm to output the $n-m+1$ integers $d_i$.
\end{definition}

\begin{definition}[Text-to-pattern approximate Hamming distance] \label{def:ham_approx}
    Given an instance of \ref{def:ham_approx} and a real number $\eps \in (0, 1)$, find a value $\hat{d}_i$ such that $(1-\epsilon)d_i \leq \hat{d}_i \leq (1+\epsilon)d_i$ for each $i$.
\end{definition}

\subsection{Near-linear algorithm}

Kopelowitz and Porat \cite{kopelowitz18} introduced a near-linear Monte-Carlo algorithm to solve the text-to-pattern approximate Hamming distance problem with running time $O(\eps^{-1} n \log n \log m)$ and failure probability $n^{-(c-1)}$, where $c$ is a constant you can set arbitrarily, and which linearly increases the runtime of the algorithm.
Let $\Sigma$ denote the common alphabet of $T$ and $P$.

One of the main tools they used is the following algorithm, developed by \cite{fischer74}.

\begin{theorem} \label{thm:sigma_fft}
    If the alphabet size is $\abs{\Sigma}$, there exists an algorithm with $O(\abs{\Sigma} n \log m)$ runtime that computes the Hamming distance exactly.
\end{theorem}
\begin{proof}
    The Hamming distance $d_i$ is the number of mismatching characters between $T_i$ and $P$, i.e. the number of $j$ with $t_{i+j} \neq p_j$.
    This is equal to $m$ minus the number of matching characters (number of $j$ with $t_{i+j} = p_j$).
    For a specific character $\sigma \in \Sigma$, we can use a convolution to compute all the contributions from matching characters where both characters are $\sigma$ in $O(n \log m)$ time.
    Specifically, for each $i$, we can compute the number of $j$ such that $t_{i+j} = p_j = \sigma$.

    To achieve this, we simply replace all characters $s$ with $1$ and all other characters with $0$, reverse $P$, then use FFT to compute a convolution.
    We can repeat this for all $\sigma \in \Sigma$ to compute the total number of matches for each position, which we can subtract from $m$ to calculate the number of mismatches for each position.
    This results in a runtime of $O(\abs{\Sigma} n \log m)$.

    The convolution can be implemented in $O(n \log m)$ time instead of $O(n \log n)$ by first splitting up $T$ into blocks of size $m$, then separately convolving each of these $n/m$ blocks with $P$ using FFT.
\end{proof}

The second idea they use is that if you randomly hash the alphabet to a smaller alphabet of size $2/\eps$, the Hamming distance for each specific substring is expected to only get multiplied by a factor of $(1 - \eps/2)$.
Specifically, if the Hamming distance of the original substring is $d_i$, then each of these $d_i$ mismatches has an $\eps/2$ chance of disappearing, if the two characters hash to the same character in the smaller alphabet.
Two characters that were the same initially always remain the same after hashing, so no new mismatches are ever created.
Thus, the expected Hamming distance of the hashed substring is $(1 - \eps/2)$.
Due to Markov's inequality, this means that we find a $(1 - \eps)$ approximation of $d_i$ with probability at least $1/2$.
Thus, if we hash to an alphabet of size $2/\eps$ $c \log n$ times and take the maximum of these Hamming distance approximations, it is a $(1 - \eps)$ approximation with probability $1 - n^{-c}$.
Using a union bound across the $\le n$ substrings, this means we get a $(1 - \eps)$ approximation of the Hamming distance for every position with probability $1 - n^{-(c-1)}$.

This leads to the following simple algorithm.
\begin{algorithm} 
\caption{Simple near-linear algorithm: ApproxHAM}
\label{alg:fft_sample}
\begin{algorithmic}
\For {$j=1$ to $c \log n$}
    \State Pick a random $h : \Sigma \to  \{1, 2, \dots, \frac{2}{\epsilon}\}$
    \State compute $x_{ji} = \op{HAM}(h(T_i), h(P))$ for all $T_i$
\EndFor
\State \Return for each $i \in [1, n]$ $\max_{1 \le j \le c \log n} x_{ji}$
\end{algorithmic}
\end{algorithm}


\subsection{Related Approximate Algorithms}

For a long time, the fastest algorithm for the problem was the one introduced by Karloff in 1993 \cite{karloff93}, with a runtime of $O(\eps^{-2}n \log n\log m)$. It was a widely held belief that no algorithm could have a better $\eps$ dependence.
However, the near-linear algorithm defined earlier improved the epsilon dependence to $O(\eps^{-1})$. 

Recently, Chan et al. \cite{chan2024} discovered a connection between the text-to-pattern approximate problem with the 3SUM problem.
Using Fredman's trick and Equality Product, they reduced the epsilon dependence to approximately $O(\eps^{0.93})$ using an algorithm of running time $\tilde{O}(\epsilon^{-0.93}n)$, where $\tilde{O}$ hides away the log factors.
Due to the complicated nature of the algorithm, we decided to omit this algorithm from implementation.

\subsection{Exact Algorithms}

For the exact version of the problem, for a long time, the best algorithm was Abrahamson's algorithm \cite{abrahamson87} with a deterministic runtime of $O(n \sqrt{m \log m})$.
We outline the algorithm here: 

Call a character in $\Sigma$ heavy if it appears more than $H$ times in $P$, and light otherwise.
We will set the value of $H$ later.
We will compute the alignments of heavy and light characters separately, where $a_i = m - d_i$ is the number of aligned characters between $T_i$ and $P$.

\begin{itemize}
    \item Heavy characters:
    Note that there are at most $\frac{m}{H}$ heavy characters in $P$.
    For each heavy character, we can apply Theorem \ref{thm:sigma_fft} to determine the alignments in $O(n \log m)$ time.
    The total runtime for all heavy characters is $O(\frac{mn}{H} \log m)$.
    \item Light characters:
    For each character, create a list of all the indices where that character appears in $P$.
    Iterate over all pairs of indices $i$ of $T$ and if $t_i$ is light, iterate over all the indices $j$ where it appears in $P$ and increment $a_{i-j}$.
    This takes $O(n H)$ time.
\end{itemize}
Since $d_i = m - a_i$, we have an algorithm that computes exact text-to-pattern Hamming distance.
Set $H = \sqrt{m \log m}$, and the combined runtime is $O(\frac{mn}{\sqrt{m \log m}} \log m + n \sqrt{m \log m}) = O(n \sqrt{m \log m})$.
Chan et al. later improved this runtime bound to $O(n \sqrt{m})$ \cite{chan2024}, by proving a key lemma on counting the elements of all values in the sum of two sets.

\section{Optimizations}

A number of simple optimizations can be made to Algorithm $\ref{alg:fft_sample}$ at generally no cost:

\begin{itemize}
    \item The algorithms we use always underestimate the answer, computing a $\hat{d}_i$ satisfying $(1-\eps)d_i \leq \hat{d}_i \leq d_i$. We can instead compute a $(1 - \eps)/(1 + \eps)$ approximation of the answer and the multiply it by $(1 + \eps)$ to get a $(1 \pm \eps)$ approximation.
    For small $\eps$, this almost doubles the amount of error we are allowed, approximately halving the runtime of Algorithm $\ref{alg:fft_sample}$.
    \item If the number of FFT calls we would make is greater than the alphabet size, we can switch to the exact algorithm of Theorem \ref{thm:sigma_fft} instead of sampling.
    \item If there are items with very small or very large frequencies, we can treat them as light or heavy characters as in Abrahamson's square root algorithm to reduce the alphabet size.
    This is not too useful for the original algorithm, but it can make heuristics more robust if they rely on a small alphabet size or the fact that there are nor frequent elements.
    \item If $n$ or $m$ are small, we can switch to brute force, which has a very good constant factor in practice.
\end{itemize}

\subsection{Balanced hashing} \label{sec:balenced_hash}

We can also restrict the hash function of Algorithm \ref{alg:fft_sample} to something slightly more stable.
Instead of hashing each $\sigma \in \Sigma$ to a random value in $\{1, 2, \ldots, 2/\eps\}$, we instead take the list of characters $[1, 2, \ldots, \abs{\Sigma}]$, shuffle it randomly, then hash the $i$-th element to $i \pmod{2/\eps}$.
This still satisfies the property that any two elements hash to the same value with probability at most $\eps/2$, so the original analysis is still valid.

In general, a useful way to think about our hash functions is as follows.
We have a graph with $\abs{\Sigma}$ nodes that we color with $k = \ceil{2 / \eps}$ colors.
Every edge that is monochromatic, i.e. both endpoints have the same color, represents a collision.
The above set of hash functions minimize the number of monochromatic edges, and all edges are equally likely to be monochromatic due to symmetry.
Thus, each edge still has at most a $\eps/2$ chance of being monochromatic.

\section{Heuristics}

In this section we improve on Algorithm \ref{alg:fft_sample} for certain input classes.

\subsection{Terminating early} \label{sec:term_early}

While running Algorithm \ref{alg:fft_sample}, if at any point we find that for a specific position, the $\tilde{d_i}$ we have computed so far is at least $(1 - \eps)m$, then we know for sure that we have found a $(1 \pm \eps)$ approximation for that position, since the true answer is guaranteed to be between $\tilde{d_i}$ and $m$.
There are a few optimizations we can do based on this.

After a specific sampling round, we can count the number of positions with $\tilde{d_i} < (1 - \eps)m$ in linear time.
Let this value be $k$.
\begin{itemize}
    \item If $k = 0$, we can terminate the algorithm immediately.
    \item If we want our algorithm to succeed with probability $1 - 2^{-c_1}$, then we can decrease the remaining number of sampling rounds to $\log k + c_1$.
    \item If $k$ is sufficiently small, we can switch to the brute force algorithm, which takes $O(km)$ time and has a very good constant factor.
    \item If we suspect the string has a few characters with high frequency that cause a lot of matches and prevent us from terminating early --- since they cause many of the $d_i$ values to be $\ll m$ --- then we can use a single FFT convolution for each high frequency character to count the number of matches of that character for each offset.
    This allows us to get a better upper bound than $m$ on the number of possible mismatches at an offset $i$ of the text string.
    If we find that there are $a_i$ aligned/matched characters between $T_i$ and $P$, then $d_i \le m - a_i$, so we can terminate if our current lower bound $\tilde{d_i}$ satisfies $\tilde{d_i} \ge (1 - \eps)(m - a_i)$.
\end{itemize}

This kind of optimization could provide a significant speedup to the algorithm for practical data where many of the substrings are not at all similar and there are a few matches or almost matches.

We prove that for the case when each character of the input data is uniformly chosen from $\Sigma$, a short circuiting algorithm that terminates when $k = 0$ finishes after one round with high probability for most reasonable input parameters.
To do this, we analyze the probability that for a specific offset in the input, the $\tilde{d_i}$ we would compute after a single round is $< (1 - \eps)m$.

We use the balanced hashing function described in Section $\ref{sec:balenced_hash}$.
For a specific $j$, the probability that $t_{i+j}$ and $p_j$ hash to the same character is at most $1/\abs{\Sigma} + 2/\eps$ for any balanced hash function.
Note that the $1/\abs{\Sigma}$ term is only necessary if the reduced alphabet size $2/\eps$ does not divide the size $\abs{\Sigma}$ of the original alphabet.
If it does, then the probability is exactly $2/\eps$.
If $\abs{\Sigma} \ge 6/\eps$, this probability is at most $(2/3)\eps$.
If $\abs{\Sigma} < 6/\eps$, we can simply run FFT for each character in the original alphabet, which takes $O(\abs{\Sigma} n \log m) = O(\eps^{-1} n \log m)$ time.

For a specific substring, since all characters are generated independently at random, we can use a Chernoff bound to bound the number of characters that match after being hashed.
This is valid, because the match probability of $1/\abs{\Sigma} + 2/\eps$ doesn't depend on the hash function; any balanced hash function obtains this bound.
The expected number of matches is at most $\mu = (2/3)\eps m$.
The probability that more than $\eps m$ characters match is less than $e^{\mu \cdot 1/2^2 \cdot 1/3} = e^{m \eps/18}$.
If $m > 36 \ln(n)/\eps$, then the probability that each position is bad is at most $1/n^2$.
Using a union bound, the probability of at least one character being bad is at most $1/n$.
Thus, with high probability our algorithm terminates after one round.

If we terminate in one round, the time complexity is $O(\eps^{-1} n \log m)$.
If $m < 36 \ln(n)/\eps$, then we can run the $O(nm)$ brute force to get a runtime of $O(\eps^{-1} n \log(n))$.
Thus, we get a runtime of $O(\eps^{-1} n \log m)$ or $O(\eps^{-1} n \log n)$ in all three cases, which is a log factor faster than on arbitrary data.

By our optimization, this hash function has the property that each character in $\{1, \dots, \frac{2}{\eps} \}$ is mapped to by $\frac{|\Sigma|\eps}{2}$ characters. Recall that $x_{ji} = \op{HAM}(h(T_i), h(P))$. The probability that two distinct characters remain distinct under the hash function for a position $j$ is $\left(\frac{\abs{\Sigma}\eps}{2} - 1\right) / \abs{\Sigma} \leq \frac{\eps}{2} $. \subsection{An efficient scoring scheme by the TP bucket mass metric}
In this subsection we introduce the TP scoring heuristic, explain its
motivation, and analyze a simple binary setting in which it reduces the number of required projections from $\Theta(\log n)$ to $O(1)$.

\subsubsection{Ranking hashes by text-pattern (TP) bucket mass}

First, I will briefly describe the motivation behind the TP hash-scoring scheme. 
In the real-world sequences we investigated (e.g.\ protein and DNA strings), we observed a tendency for a near-random distribution of characters, but the distribution is rarely perfectly uniform (see Section \ref{sec: real_world_data}).
% For example, amino acid frequencies in proteins vary but exhibit common patterns: Leucine, Serine, Alanine, Glycine, and Lysine are often the most abundant (around 7-10\%), while Tryptophan and Methionine are typically the least common (around 1-2\%). Natural language text is similarly skewed toward common letters and words.

This tendency for random-like data from a skewed distribution to appear in nature inspired us to develop a hash scoring scheme that favors hash functions which isolate frequent symbols. 
On such inputs, collisions involving frequent symbols (for example, a dominant symbol like $0$ that appears with probability $0.8$) have a much larger effect on the projected Hamming distance than collisions between two rare symbols. \KP's algorithm selects a random 2-universal hash $h:\Sigma\to\{1,\dots,B\}$ in each round, guaranteeing that any fixed pair of distinct keys collides with probability at most $1/B$, where $B=2/\varepsilon$ is the number of buckets.
However, computing $\operatorname{HAM}(h(T_j),h(P))$ via FFT in each round costs $O(n\log m)$ time with a large constant factor, so it is desirable to discard hash functions that are likely to be ``bad'' (for example, those that cause many collisions between frequent characters) before doing FFT on the filtered candidate pool. 
The TP score $\score_{TP}(h)$ is designed precisely to rank hash functions by how well they separate high-mass buckets of $T$ and $P$, so that we can spend FFT time only on the most promising candidates.

\begin{definition}[TP Score Function] \label{def:scoreTP}
    For a hash function $h: \Sigma\to\{1, 2, \dots, B\}$, define
    \[
    \text{score}_\text{TP}(h)=\sum_{b=1}^{B} f_T(b) f_P(b),
    \]
    Where $f_T(b)$ is the total number of occurrences of symbols that hash to bucket $b$ in $T$, and similarly $f_P(b)$ is the total number of occurrences of symbols that hash to bucket $b$ in $P$.
    
\end{definition}

\begin{algorithm}
\caption{ApproxHAM Heuristic TP}
\label{alg:HeuristicTP}

\begin{algorithmic}
\State Pick a sample of $S=c_0\log n$ random hash functions, $H=\{ h_1, ..., h_S \}$ where each $h : \Sigma \rightarrow  \{1, 2, \dots, B\}$ with $B=\frac{2}{\epsilon}$, is chosen independently from a 2-universal hash family.

\State Sort the hash functions in increasing order of $\score_{TP}(h)$ (Definition \ref{def:scoreTP}), obtaining an ordering $h_{(1)}, \dots, h_{(S)}$.
% \[
% \text{score}_{TP}(h)=\sum_{b=1}^{B} f_T(b) f_P(b) ,
% % \text{ where }
% % M_b= (\# \text{positions $i$ where $h(s_i)=b$}) + (\# \text{positions $j$ where $h(t_j)=b$}).
% \]
% Where $f_T(b)$ is the total number of occurrences of symbols that hash to bucket $b$ in $T$, and similarly $f_P(b)$ is the total number of occurrences of symbols that hash to bucket $b$ in $P$.
\For {$i=1$ to $R$ where $R=c_1\log n\le S$}
    \State Choose $h=h_{(i)}$ (the $i$-th hash function in the sorted $H$)
    \State compute $x_{ij} = \op{HAM}(h(T_j), h(P))$ for all $T_j$
\EndFor
\State \Return $ \{\max_j x_{ij}\}$
\end{algorithmic}
\end{algorithm}

For any input, Kopelowitz and Porat showed that there exists a constant $c_0$ such that Algorithm \ref{alg:fft_sample} produces a $(1\pm \epsilon)$ approximation with high probability after $c_0 \log n$ iterations.
In our setting, we first draw the same number $S = c_0 \log n$ of independent 2-universal hash functions $H = \{h_1,\dots,h_S\}$ as in Algorithm \ref{alg:fft_sample}, and then apply them in a different order.
If we choose $c_1 = c_0$ and set $R = S$, Algorithm \ref{alg:HeuristicTP} applies exactly the same set of hash functions as Algorithm \ref{alg:fft_sample}.
Each position ultimately takes the maximum over the same $S$ projected Hamming distances, and permuting the hashes does not change this maximum.
Therefore, for any input, Algorithm \ref{alg:HeuristicTP} with $R = c_0 \log n$ achieves the same $(1\pm \epsilon)$ guarantee as Algorithm \ref{alg:fft_sample}.
The remaining question is to identify input families on which taking $R < c_0 \log n$ still obtains a $(1\pm \epsilon)$ approximation with high probability.


\subsubsection{Heuristic TP achieves $(1\pm\epsilon)$ Approximation in $O(1)$ iterations for a constant\\ alphabet size}

To simplify the analysis, we'll consider the case where the input is restricted to a binary alphabet $\Sigma=\{0,1\}$.

Call a hash function \textit{good} if $h(0)\ne h(1)$, and \textit{bad} otherwise.
Since ApproxHAM succeeds with high probability in $c_0\log n$ iterations, and we pick $H$ to be the same $S=c_0\log n$ hash functions as ApproxHAM, we know at least one of the $S$ hash functions must be \textit{good} w.h.p. Otherwise, if all $S$ hash functions are bad, neither algorithms would achieve $(1\pm \eps)$ accuracy for small $\eps$.

Let $t_0,t_1$ for the total number of zeros and ones in $T$, and
$p_0,p_1$ for the total number of zeros and ones in $P$, so
$t_0+t_1=n$ and $p_0+p_1=m$.

If $h$ is bad, then both $0$ and $1$ map to the same bucket $b_0$, so $f_T(b_0) = t_0+t_1 = n$ and $f_P(b_0) = p_0+p_1 = m$, and all other buckets have zero mass. Thus
$$\score_\text{TP}(h_{bad}) = f_T(b_0) \ f_P(b_0) = nm.$$

If $h$ is good, say $h(0)=b_0$ and $h(1)=b_1$ with $b_0\neq b_1$, then
\[
f_T(b_0)=t_0,\ f_P(b_0)=p_0,\qquad
f_T(b_1)=t_1,\ f_P(b_1)=p_1.
\]
Therefore,
\[
\score_\text{TP}(h_{good})
  = t_0 p_0 + t_1 p_1
  < (t_0+t_1)(p_0+p_1) = nm = \score_\text{TP}(h_{bad}),
\]
% $$\score_{TP}(h_{good}) = f_T(h_{good}(0)) \ f_P(h_{good}(0)) 
% + f_T(h_{good}(1)) \ f_P(h_{good}(1)) < nm.$$
since $t_0p_1 + t_1p_0 > 0$ whenever both symbols appear in $T$ and $P$. Thus, a good hash preserves all mismatches, and a bad hash collapses $0$ and $1$, so all mismatches are destroyed and $x_j=0$.

% Assuming that ApproxHAM achieves a $(1\pm \eps)$ approximation in $c_0\log n$ rounds with high probability, there is at least one \textit{good} hash function in the sample $H$. Since $\score_{TP}(h_{good}) < \score_{TP}(h_{bad})$ always, sorting the candidates by $\score_{TP}(h)$ will place any \textit{good} hash function above any bad one. Thus, \textbf{Algorithm 2} terminates in one iteration with high probability.

For a random hash in the sample $H$, $\Pr[h(0)=h(1)] = 1/B$, so
$\Pr[h(0)\neq h(1)] = 1-1/B$. The probability that all $S$ candidates
are bad is at most $(1/B)^S$. With probability $1-(1/B)^S$, at least one good hash appears in the sample and, by the inequality above, every such good hash has strictly smaller $\score_{TP}$ than any bad hash. Thus sorting by $\score_{TP}$ places a good hash first, and taking $R=1$ in Algorithm \ref{alg:HeuristicTP}, we compute the exact Hamming Distance with probability at least $1-(1/B)^S$.

In particular, if we choose $S = c_0 \log n$ for a suitable constant
$c_0$ as proven in \KP's paper, then $(1/B)^S = n^{-\Omega(1)}$ and one iteration of Heuristic TP suffices with high probability. This demonstrates that in the proposed binary setting, scoring hashes according to $\score_\text{TP}$ can reduce the number of required projections from $\Theta(\log n)$ to $O(1)$ on certain input families.

Although we were not able to generalize this analysis rigorously for arbitrarily large alphabets, we conjecture that a similar pattern holds. The analysis above, despite assuming a highly-simplified binary model, may capture the basic mechanism by which TP scoring prefers hashes that separate frequently occurring text and pattern symbols.

For a general constant-size alphabet, one can view each symbol $a\in\Sigma$ as the ``main'' symbol (1) and collapse all others to a background symbol (0), yielding a similar two-symbol abstraction.
The same analysis holds for larger alphabet sizes where mismatches are restricted to pairs $(a,x)$ for a single ``main'' character $a\in\Sigma$ with any other character $x\ne a$. However, whether this pattern generalizes to other input classes remain a preliminary hypothesis, and require further analysis.

We also observed that the TP Heuristic performs well in adversarial cases, achieving significantly lower approximation ratios than the base ApproxHAM algorithm (KP Projection) for cyclic and k-difs data with half the runtime (see Section \ref{sec:results}).

\subsubsection{Runtime}
The precomputation of symbol frequencies takes $O(n+m)$ time. 
Given these frequencies, scoring each of the $S = c_0 \log n$ candidate hash functions takes $O(B) = O(1/\epsilon)$ time, so the scoring step costs $O\left(\frac{1}{\epsilon}\log n\right)$ in total.
Sorting the $S$ hash functions by score takes $O(S \log S) = O(\log n \log \log n)$.
The rest of the work is the same as in ApproxHAM. The total runtime is
$$O\left(\frac{1}{\epsilon} \log n + \frac{n}{\epsilon} \log n\log m\right)=O\left(\frac{n}{\epsilon} \log n\log m\right),$$
which is the same asymptotic runtime as ApproxHAM.

Empirically, we have also shown that the required constant factor is often smaller in several benchmark datasets (see Section \ref{sec:results}), making Heuristic TP a more efficient algorithm in practice.

\section{Experiments}

\subsection{Setup}

We implemented all algorithms in C++.
We use AtCoder's template library for the main part of the FFT implementation \cite{ac_library}.
The experiments were conducted on a MacBook Pro with an Apple M2 (ARM64) processor running macOS. We compiled with \texttt{g++} version \texttt{13.3.0} and \texttt{-O3} optimization level. 
The code is available at \href{https://github.com/Balint-R/6_5220-project}{https://github.com/Balint-R/6\_5220-project}.



\subsection{Algorithms tested}
We tested three approximation algorithms (\textsc{KP Projection}, \textsc{KP Projection} with Short Circuit, \textsc{Heuristic TP}), and compared their performance against two exact algorithms (\textsc{Brute Force}, \textsc{Sqrt}).

\begin{itemize}
    \item \textsc{Brute Force} (\texttt{ham\_dist\_bf})
    
    This is a $O(nm)$ brute force implementation that computes the answer for each $T_i$ one at a time, by counting the number of $j$ where $t_{i+j} \neq p_j$.
    
    \item \textsc{Sqrt} (\texttt{ham\_dist\_sqrt})
    
    This is a $O(n \sqrt{m \log m})$ time deterministic algorithm similar to the one presented by Abrahamson \cite{abrahamson87}.
    It focuses on counting matches instead of mismatches.
    For each character, it computes $f_a$ and $f_b$, the frequency of the character in the two strings.
    If the product $f_af_b$ is above a certain threshold based on $n$ and $m$, then it uses FFT for that character, otherwise, it enumerates all $f_af_b$ pairs of indices where the character appears to count its contribution.
    
    \item \textsc{KP Projection} (\texttt{ham\_dist\_proj})
    
    This is the main $O(\eps^{-1} n \log n \log m)$ FFT sampling algorithm described earlier as Algorithm \ref{alg:fft_sample}.
    We apply the optimization where we set $\eps' = 1 - (1 - \eps)/(1 + \eps)$, calculate an $1 - \eps'$ approximation by repeatedly projecting to an alphabet of size $\ceil{2/\eps'}$, then multiply the answer by $(1 + \eps)$ to get a $(1 \pm \eps)$ approximation.
    We always pick a balanced hash function (see section \ref{sec:balenced_hash}) by shuffling the order of the elements in $\Sigma$, then hashing the $i$-th one to $i \pmod {\ceil{2/\eps'}}$.
    We do not implement any other optimizations, such as eliminating very low or very high frequency characters, since this might make it more difficult to observe the runtime of the base algorithm.
    
    \item \textsc{KP Projection} with Short Circuit (\texttt{ham\_dist\_proj\_sc})
    
    This is also Algorithm \ref{alg:fft_sample}, but we also implement a version of short circuiting, as described in Section $\ref{sec:term_early}$.
    Let $k$ be the number of estimations below $(1 - \eps')m$.
    We terminate if $k = 0$.
    Otherwise, we decrease the number of remaining rounds to $\log_2(k) + 3$ (if this would be a decrease).
    
    \item \textsc{Heuristic TP} (\texttt{HammingDistanceHeuristic})
    
    This is the Heuristic (Algorithm \ref{alg:HeuristicTP}) with TP scoring (Definition \ref{def:scoreTP}) aimed to minimize hash collisions among frequent characters. We apply the same optimizations as the \textsc{KP Projection} algorithm, except for the hash-selection mechanism. Instead of picking a random balanced hash function as described in Section \ref{sec:balenced_hash}, we pick the best $R\le c_0\log n$ hash functions with the lowest $\score_\text{TP}(h)$ (Definition \ref{def:scoreTP}), with an empirically determined $R$ to achieve $(1\pm\eps)$ accuracy.
    % We empirically determined that running  \textsc{Heuristic TP} for half the iterations yielded the same or lower approximation ratio as the base \textsc{KP Projection} on all inputs tested.
\end{itemize}

Our synthetic test cases are designed to evaluate the strengths and weaknesses of all the algorithms, especially when compared against each other. These test cases meet the following criteria.
\begin{itemize}
    \item For each algorithm, we should have a family of test cases that maximize its runtime.
    \item For each sampling based approximation algorithm, we should have a family of test case that maximize the number of iterations it takes until its answer becomes correct (or at least test cases which makes this large).
    \item For each optimization/heuristic we propose, we should have a family of test cases where that heuristic performs better than the other algorithms.
\end{itemize}

Furthermore, we design test cases where an easy deterministic optimization does not easily solve the problem.
In particular, test cases with extremely small $m$ (e.g. less than $\Theta(\eps^{-1} \log n \log m)$) are not interesting, because we could easily run the brute force algorithm instead of our approximation algorithms.
Test cases where there are characters with very low or very high frequency are also not good, because we could easily count the frequencies of the characters at the start, and use the part of the sqrt algorithm optimized for low or high frequency characters to eliminate these characters before running the reset of the algorithm (if not all characters were eliminated).
To achieve these goals, we use the following families of test cases.

\begin{itemize}
    \item \texttt{uniform}:
    Each character is chosen independently and uniformly at random from $\Sigma$.
    
    In theory, this should achieve the worst case runtime for \texttt{ham\_dist\_brute} when $m$ is about $0.5n$.
    It gets worst case runtime for \texttt{ham\_dist\_sqrt} when $\abs{\Sigma} = \Theta(m/\log(m))$.
    It gets the worst case runtime for \texttt{ham\_dist\_proj} when $m = \Theta(n)$.
    It gets a very good runtime for \texttt{ham\_dist\_proj\_sc}, as we proved in Section \ref{sec:term_early} that it usually terminates after one round, which is the best possible.

    \item \texttt{cyclic}:
    We set the $i$-th character of $T$ to $i \pmod{\abs{\Sigma}}$ and the $i$-th character of $P$ also to $i \pmod{\abs{\Sigma}}$.
    
    This test case is most useful when $\abs{\Sigma} = n^{1/3}$ and $m = n^{2/3}$.
    In this case, there are $n^{1/3}$ distinct characters, each with frequency product $n$.
    Thus, both the low and high frequency algorithms would take $\Omega(n^{4/3})$ time, so this case is not trivial.
    Brute force would also take $\Omega(n^{5/3})$ time, since $m$ is not small.

    This test case has $n^{2/3}$ substrings of $T$ that perfectly match $P$, giving \texttt{ham\_dist\_proj\_sc} a bad runtime, since the approximation for those indices never gets close to $m$ (since it always stays at $0$).

    \item \texttt{k\_difs}:
    Let $k = \ceil{1/\eps'} - 1$.
    Start with the same $T$ and $P$ as in \texttt{cyclic}.
    For each of the $n/m$ non-overlapping substrings of $T$ of length $m$, choose $k$ distinct characters $s_1, s_2, \ldots, s_k$, and a sequence of replacements $r_1, r_2, \ldots r_k$ such that all elements of $\{s_1, s_2, \ldots s_k, r_1, r_2, \ldots r_k\}$ are distinct. Replace each instance of $s_i$ in this substring with $r_i$.

    We again analyze the case where $\abs{\Sigma} = n^{1/3}$ and $m = n^{2/3}$.
    This is again not trivial, since the frequencies of characters are about the same as in \texttt{cyclic}, so there are no extremely low or high frequency characters.

    The idea of this test case is that it tries to cause \texttt{ham\_dist\_proj} to take a long time to get a good estimation.
    For each of the $n/m$ non-overlapping substrings, if even one of the $k = \ceil{1/\eps'} - 1$ edges get mapped to the same color, then the algorithm already finds a worse than $(1 - \eps')$ approximation.
    The probability of this happening is constant for each position, so we need to sample $\Omega(\log n^{1/3})$ times to have a constant probability of success.
    % TODO: make analysis better
\end{itemize}

\subsection{Experiment Results on Synthetic Data}
\label{sec:results}
For each of the input families above, we measured the runtime and approximation ratios of the five algorithms under different values of $n$, $m$, $\abs{\Sigma}$, and $\eps$.
Each data point is obtained by generating $5$ test cases using the same parameters but a different random seed, and taking the average of the run times.

Magic short circuiting means measuring the time it takes to reach the correct approximation ratio.
Note that this could not actually be implemented in practice, since it requires you to know the answer beforehand to know when to terminate.
However, if we find that this algorithm is significantly better than without magic short circuit on all inputs, then we could simply decrease the maximum number of iterations we run our algorithm for.

\subsection{Real World Data}
\label{sec: real_world_data}
To complement our synthetic benchmarks, we evaluated all algorithms on real biological sequences. Our goal was not to solve a specific bioinformatics application, but to test whether approximate Hamming distance can offer practical advantages on large, naturally occurring strings with diverse structural properties.

As a hypothetical scenario, imagine we found a new protein in species $A$ (e.g. humans), and we wanted to see if the protein evolved from species $B$ (e.g. gorillas). Additionally, suppose that in this hypothetical protein, any indel mutation is deadly, so we are restricted to substitutions. In the real world, this is a highly simplified assumption, but in this scenario we might compute approximate Hamming distance to identify homologs with up to $k$ substitutions in species $B$. Standard DP algorithms for global sequence alignment such as Needleman-Wunsch and Smith-Waterman are $O(mn)$, so approximate Hamming could be used as a fast first filter for aligning new proteins against a large database (although Hamming Distance is rarely used in practice because it does not account for indels).

For the text string ($T$), we used the human proteome (UniProt proteome ID UP000005640 \cite{uniprot}), which is around $31$ million amino acids long.

We chose four proteins as pattern strings ($P$). Protein sequences are obtained from Uniprot, using the accessions Q8WZ42 (Titin), P20929 (Nebulin), Q8WXI7 (MUC16), and P0DTC2 (SARS-CoV-2 Spike) \cite{uniprot}.
\begin{itemize}
    \item Titin (34,350 aa's): This is the longest known protein in humans with high complexity (near-random, very few repeated windows).
    
    \item MUC16 (14,507 aa's): This is the second-longest known human protein with many serine/threonine-rich tandem repeats. The composition is highly skewed toward S/T (around $18\%$ each), and other amino acids are rare ($< 9\%$ each).

    \item Nebulin (8,525 aa's): A highly repetitive protein composed of repeated actin-binding motifs, but less skewed than MUC16.

    \item SARS-Cov2 Spike protein (1,273 aa's): A practically meaningful protein with a substantially shorter sequence, included to mirror realistic applications.
    
\end{itemize}

Across all real-world patterns examined, the behavior of the algorithms mirrors---but also meaningfully deviates from---that of the synthetic data in Section \ref{sec:results}. Instead, runtimes change more smoothly with $\eps$ and follow the same general ordering between algorithms on all protein sequences. This stands in contrast against certain adversarial generators (specifically \texttt{cyclic} and \texttt{k-difs}), which showed sharper deviations in runtime.

\begin{itemize}
    \item On Titin, the long pattern string and near-random structure allows the approximate algorithms (specifically the magic short-circuiting versions) to outperform the exact algorithms (Brute Force and Sqrt). We noticed that in most runs, the approximate algorithms reached $(1\pm \eps)$ accuracy in one iteration.

    \item The highly skewed and repetitive composition of MUC16 makes different windows of the text appear similar under projection, making it challenging for hashing-based algorithms to achieve a good approximation ratio. However, the algorithms still performed well due to the long pattern length.

    \item On Nebulin, the approximation algorithms still perform fairly well, but less so compared to a longer, more random protein like titin.

    \item Because of the shorter length of the SARS-Cov2 Spike protein, Brute Force and Sqrt outperformed the approximation algorithms in almost all values of $\eps$ due to constant factor domination.
\end{itemize}






\section{Conclusion}

Overall, the exact algorithms are relatively fast, and the basic approximation algorithm is only better if the input is extremely large and $\eps$ is lenient.
The short circuiting version does provide a significant advantage for uniformly distributed data.
The lack of interesting real world data makes it difficult to determine which algorithm would be best for large inputs, since it would depend on the distribution of the data.
We ran \texttt{ham\_dist\_proj} for $\log_2(n) + 1$ iterations, which in theory we only proved has about a $1/2$ chance of success.
However, in practice, the algorithm seems to get an approximation much faster, with the magic short circuiting version always being at least $3$ times faster.
This is because it is hard to construct strings where every substring of $T$ is bad for the approximation algorithm, since substrings overlap.
It might be possible to prove that the algorithm converges faster by a constant factor than stated in the original paper, if one can find a useful way to examine the interactions between overlapping substrings.
